# Module: mock_transport

### Introduction
The `mock_transport` module provides a `MockTransport` class, designed for testing and development purposes within the HTTPX library. It allows users to inject custom request handlers, enabling predictable responses for requests without making actual network calls.

### Core Functionality

#### `MockTransport`
The `MockTransport` class is a versatile transport implementation that allows for the interception and handling of HTTP requests programmatically. It's particularly useful for unit testing HTTPX clients by providing predefined responses or simulating specific network conditions.

**Components:**

*   **`httpx._transports.mock.MockTransport`**:
    *   **Purpose**: Implements both synchronous and asynchronous transport interfaces, enabling it to be used with both `Client` and `AsyncClient`. It routes requests to an internal `handler` function.
    *   **`__init__(self, handler: SyncHandler | AsyncHandler) -> None`**:
        *   Initializes the `MockTransport` with a `handler` function. This handler can be either a synchronous or asynchronous callable that takes a `Request` object and returns a `Response` object.
    *   **`handle_request(self, request: Request) -> Response`**:
        *   Synchronous request handling method.
        *   Reads the request body.
        *   Passes the `Request` object to the `self.handler`.
        *   **Raises**: `TypeError` if an asynchronous handler is provided when used with a synchronous client.
        *   **Returns**: A `Response` object generated by the handler.
    *   **`handle_async_request(self, request: Request) -> Response`**:
        *   Asynchronous request handling method.
        *   Asynchronously reads the request body.
        *   Passes the `Request` object to the `self.handler`.
        *   If the `handler` is an `async` function, it awaits its result before returning.
        *   **Returns**: A `Response` object generated by the handler.

### Architecture

The `mock_transport` module, specifically the `MockTransport` class, acts as a critical component in the `transports` layer for testing. It inherits from `BaseTransport` and `AsyncBaseTransport`, ensuring compatibility with both synchronous and asynchronous client operations. It relies on external `Request` and `Response` models from the `models` module and uses handler type definitions from the `types` module.

### How the Module Fits into the Overall System

The `mock_transport` module provides a specialized transport mechanism for scenarios where actual network requests are undesirable, primarily for testing and mock data provision. It implements the core transport interfaces defined in [base_transports.md](base_transports.md), allowing it to be seamlessly integrated with `httpx._client.Client` and `httpx._client.AsyncClient` from the [client.md](client.md) module. By injecting a `MockTransport` into a client, developers can control the responses their client receives, making it an invaluable tool for ensuring application reliability and correctness.
