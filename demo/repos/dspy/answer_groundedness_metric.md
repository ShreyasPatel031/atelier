# `answer_groundedness_metric`

## Introduction

The `answer_groundedness_metric` module is a vital component within the DSPy evaluation framework, specifically designed for the automatic assessment of a system's response groundedness. It provides the `AnswerGroundedness` signature, which leverages language models to evaluate how well system-generated answers are supported by provided retrieval contexts, ensuring the factual accuracy and reliability of the output.

## Core Functionality

The primary function of this module is encapsulated in the `AnswerGroundedness` class. This class defines a `Signature` that guides a Language Model (LLM) to perform a structured evaluation:

*   **Claim Enumeration**: It identifies and lists all non-trivial or check-worthy claims present in the system's response.
*   **Contextual Discussion**: It discusses the extent to which each claim can be deduced from the `retrieved_context` and common sense.
*   **Groundedness Score**: It calculates a fractional score (out of 1.0) representing the proportion of the system response that is supported by the provided context.

### `AnswerGroundedness` Signature

```python
class AnswerGroundedness(Signature):
    question: str = InputField()
    retrieved_context: str = InputField()
    system_response: str = InputField()
    system_response_claims: str = OutputField(
        desc="enumeration of non-trivial or check-worthy claims in the system response"
    )
    discussion: str = OutputField(desc="discussion of how supported the claims are by the retrieved context")
    groundedness: float = OutputField(
        desc="fraction (out of 1.0) of system response supported by the retrieved context"
    )
```

**Input Fields:**

*   `question`: The original question asked.
*   `retrieved_context`: The context (e.g., documents, passages) retrieved by the system.
*   `system_response`: The answer generated by the system.

**Output Fields:**

*   `system_response_claims`: An enumeration of distinct claims made in the system response.
*   `discussion`: A detailed discussion analyzing how well each claim is supported by the `retrieved_context`.
*   `groundedness`: A float value (0.0 to 1.0) indicating the fraction of the system response that is grounded in the `retrieved_context`.

## Architecture and Component Relationships

This module integrates into the broader DSPy evaluation ecosystem as an auto-metric. The `AnswerGroundedness` class inherits from DSPy's `Signature` base class, allowing it to be executed by any configured Language Model to perform its evaluation logic. It acts as a specialized instruction set for the LLM to assess groundedness.

## Integration with the Overall System

The `answer_groundedness_metric` module is part of the `dspy_evaluation` package, specifically nestled under `auto_metrics` and `completeness_groundedness`. It provides a crucial automated metric for assessing the quality of DSPy programs, complementing other evaluation metrics. By providing a programmatic way to measure the factual support of generated answers, it enables developers to automatically optimize and refine their DSPy pipelines for greater accuracy and trustworthiness.

It relies on the [dspy_signatures](../dspy_signatures.md) module for its foundational `Signature` definition and interacts with various Language Models managed through the [dspy_clients](../dspy_clients.md) module to perform the actual evaluation inference.
