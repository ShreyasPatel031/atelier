# answer_completeness_metric

The `answer_completeness_metric` module is a crucial part of the DSPy evaluation framework, specifically designed for automatically assessing the completeness of a system's generated answers against a provided ground truth. This module focuses on understanding how well a system's response covers the key ideas present in the reference answer.

## Core Functionality

The primary component of this module is the `AnswerCompleteness` class, which serves as a DSPy Signature. This signature orchestrates the process of evaluating answer completeness by leveraging a Language Model (LLM) to perform a structured analysis.

### AnswerCompleteness Class

```python
class AnswerCompleteness(Signature):
    """
    Estimate the completeness of a system's responses, against the ground truth.
    You will first enumerate key ideas in each response, discuss their overlap, and then report completeness.
    """

    question: str = InputField()
    ground_truth: str = InputField()
    system_response: str = InputField()
    ground_truth_key_ideas: str = OutputField(desc="enumeration of key ideas in the ground truth")
    system_response_key_ideas: str = OutputField(desc="enumeration of key ideas in the system response")
    discussion: str = OutputField(desc="discussion of the overlap between ground truth and system response")
    completeness: float = OutputField(desc="fraction (out of 1.0) of ground truth covered by the system response")
```

The `AnswerCompleteness` class defines the prompt structure for an LLM to:
1.  **Identify Key Ideas**: Extract and enumerate the core ideas from both the `ground_truth` and the `system_response`.
2.  **Discuss Overlap**: Analyze the commonalities and differences between the identified key ideas from both responses.
3.  **Calculate Completeness**: Provide a fractional score (out of 1.0) indicating how much of the `ground_truth` is covered by the `system_response`.

**Inputs**:
*   `question`: The original question posed.
*   `ground_truth`: The reference or ideal answer.
*   `system_response`: The answer generated by the system being evaluated.

**Outputs**:
*   `ground_truth_key_ideas`: A detailed list or description of key ideas found in the ground truth.
*   `system_response_key_ideas`: A detailed list or description of key ideas found in the system's response.
*   `discussion`: A qualitative analysis of the overlap and differences between the two sets of key ideas.
*   `completeness`: A quantitative score (float between 0.0 and 1.0) representing the completeness.

## Architecture and Component Relationships

The `answer_completeness_metric` module is a leaf module within the DSPy evaluation hierarchy, specifically nested under `dspy_evaluation` -> `auto_metrics` -> `completeness_groundedness`. It directly utilizes DSPy's `Signature` primitive for defining its LLM interaction pattern and relies on the `dspy_clients` module for actual LLM calls.

## How the Module Fits into the Overall System

This module plays a vital role in the `dspy_evaluation` framework by providing an automated, LLM-driven metric for assessing the completeness of generated text. It integrates seamlessly with other auto-evaluation metrics found in the [auto_metrics module](auto_metrics.md) and contributes to the broader goal of comprehensive program evaluation. Its outputs can be used to fine-tune DSPy programs, giving developers a clear signal about how well their systems are covering all necessary information in their responses. It is a specialized component of the [completeness_groundedness module](completeness_groundedness.md) which focuses on both aspects.
