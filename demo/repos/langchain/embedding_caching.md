# `embedding_caching`

The `embedding_caching` module provides a robust mechanism for caching embeddings generated by various underlying embedding models. This significantly improves performance by reducing redundant computations for frequently requested embeddings.

## Architecture

The core of this module is the `CacheBackedEmbeddings` class, which acts as a wrapper around any `Embeddings` implementation. It intercepts embedding requests, checks for cached results, and only delegates to the underlying embedder if a cached version is not found.

The caching mechanism relies on a `BaseStore` interface for storing key-value pairs, where keys are the input texts and values are the generated embeddings. For convenience, the module provides a `from_bytes_store` class method that simplifies setting up the cache using a `ByteStore` and handles the necessary serialization and key encoding.

## Module Components

### `CacheBackedEmbeddings`

This is the primary class in the module, providing a caching layer for any `Embeddings` implementation.

**Initialization (`__init__`)**:
- `underlying_embeddings`: An instance of an `Embeddings` class that will be used to compute embeddings when not found in the cache.
- `document_embedding_store`: A `BaseStore` instance used to cache document embeddings.
- `batch_size`: (Optional) The number of documents to embed in a single batch before updating the store.
- `query_embedding_store`: (Optional) A `BaseStore` instance for caching query embeddings. If not provided, query embeddings are not cached.

**Methods**:

- **`embed_documents(self, texts: list[str]) -> list[list[float]]`**:
    - Embeds a list of documents. It first attempts to retrieve embeddings from `document_embedding_store`.
    - For any missing embeddings, it calls the `underlying_embeddings.embed_documents` method and then stores the results in the cache.
    - Uses `batch_iterate` for efficient processing of missing embeddings.

- **`aembed_documents(self, texts: list[str]) -> Awaitable[list[list[float]]]`**:
    - Asynchronous version of `embed_documents`, leveraging `await` for store and underlying embedder operations.

- **`embed_query(self, text: str) -> list[float]`**:
    - Embeds a single query text. If `query_embedding_store` is configured, it checks and updates that cache. Otherwise, it directly calls `underlying_embeddings.embed_query`.

- **`aembed_query(self, text: str) -> Awaitable[list[float]]`**:
    - Asynchronous version of `embed_query`.

**Class Method (`from_bytes_store`)**:

- **`from_bytes_store(cls, underlying_embeddings: Embeddings, document_embedding_cache: ByteStore, *, namespace: str = "", batch_size: int | None = None, query_embedding_cache: bool | ByteStore = False, key_encoder: Callable[[str], str] | Literal["sha1", "blake2b", "sha256", "sha512"] = "sha1") -> CacheBackedEmbeddings`**:
    - A convenience constructor that sets up `CacheBackedEmbeddings` using a `ByteStore` for caching.
    - It wraps the `ByteStore` with an `EncoderBackedStore` and handles serialization (`_value_serializer`, `_value_deserializer`) and key encoding (`_make_default_key_encoder`).
    - `namespace`: An optional string to prevent key collisions, typically set to the embedding model's name.
    - `query_embedding_cache`: Can be `True` to use the same cache as document embeddings, `False` to disable query caching, or another `ByteStore` instance for a separate query cache.
    - `key_encoder`: Allows specifying a hashing algorithm (e.g., "sha1", "blake2b") or a custom callable for encoding keys.

## How it Fits into the System

The `embedding_caching` module plays a crucial role in optimizing applications that heavily rely on embedding computations. By providing a flexible and configurable caching layer, it integrates seamlessly with existing `Embeddings` implementations and various storage backends.

-   **Integration with `classic_embeddings`**: It wraps any `Embeddings` instance, such as those found in `classic_embeddings` (e.g., `OpenAIEmbeddings`), to add caching capabilities.
-   **Dependency on `classic_storage`**: It uses `BaseStore` and `ByteStore` interfaces, which are typically implemented by storage solutions provided in modules like `classic_storage` (e.g., `LocalFileStore`).
-   **Utility from `core_utils`**: The `batch_iterate` utility is used for efficient batch processing of embedding requests, likely sourced from `core_utils`.
-   **Serialization**: It relies on internal serialization utilities (`serialization_utilities`) for converting embeddings to and from bytes for storage.

This module enhances performance and reduces costs associated with repeated calls to embedding models, making it a vital component for efficient data processing pipelines within the broader system.
