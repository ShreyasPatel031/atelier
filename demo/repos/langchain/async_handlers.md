# async_handlers

The `async_handlers` module provides the foundational asynchronous callback handler for the LangChain framework. It defines the `AsyncCallbackHandler` class, which serves as a base class for implementing custom asynchronous logic that responds to various events occurring during the execution of language models, chains, tools, agents, and retrievers. This module is crucial for building non-blocking and highly responsive applications that integrate with LangChain components.

## Architecture

The `AsyncCallbackHandler` extends the functionality of the [base_handlers](base_handlers.md) module's `BaseCallbackHandler`, providing asynchronous versions of all callback methods. It interacts with several other core modules, such as [core_messages](core_messages.md) for handling chat model messages.

The primary component within this module is the `AsyncCallbackHandler` class.

## Components

### AsyncCallbackHandler

`AsyncCallbackHandler` is an abstract base class that provides asynchronous hooks for various events within the LangChain ecosystem. Developers can subclass `AsyncCallbackHandler` and override its methods to implement custom non-blocking behavior.

Key methods include:

*   **LLM Events:**
    *   `on_llm_start(serialized, prompts, run_id, parent_run_id, tags, metadata)`: Called when a non-chat LLM starts.
    *   `on_chat_model_start(serialized, messages, run_id, parent_run_id, tags, metadata)`: Called when a chat model starts. This method explicitly handles lists of `BaseMessage` objects.
    *   `on_llm_new_token(token, chunk, run_id, parent_run_id, tags)`: Called when a new token is generated by an LLM during streaming.
    *   `on_llm_end(response, run_id, parent_run_id, tags)`: Called when an LLM finishes.
    *   `on_llm_error(error, run_id, parent_run_id, tags)`: Called when an LLM encounters an error.

*   **Chain Events:**
    *   `on_chain_start(serialized, inputs, run_id, parent_run_id, tags, metadata)`: Called when a chain starts.
    *   `on_chain_end(outputs, run_id, parent_run_id, tags)`: Called when a chain finishes.
    *   `on_chain_error(error, run_id, parent_run_id, tags)`: Called when a chain encounters an error.

*   **Tool Events:**
    *   `on_tool_start(serialized, input_str, run_id, parent_run_id, tags, metadata, inputs)`: Called when a tool starts.
    *   `on_tool_end(output, run_id, parent_run_id, tags)`: Called when a tool finishes.
    *   `on_tool_error(error, run_id, parent_run_id, tags)`: Called when a tool encounters an error.

*   **Agent Events:**
    *   `on_agent_action(action, run_id, parent_run_id, tags)`: Called when an agent performs an action.
    *   `on_agent_finish(finish, run_id, parent_run_id, tags)`: Called when an agent finishes.

*   **Retriever Events:**
    *   `on_retriever_start(serialized, query, run_id, parent_run_id, tags, metadata)`: Called when a retriever starts.
    *   `on_retriever_end(documents, run_id, parent_run_id, tags)`: Called when a retriever finishes.
    *   `on_retriever_error(error, run_id, parent_run_id, tags)`: Called when a retriever encounters an error.

*   **Other Events:**
    *   `on_text(text, run_id, parent_run_id, tags)`: Called for arbitrary text events.
    *   `on_retry(retry_state, run_id, parent_run_id)`: Called on a retry event.
    *   `on_custom_event(name, data, run_id, tags, metadata)`: Allows for handling custom-defined events.

## Relationship to Other Modules

This module is a child of the `base_handlers` module, inheriting from `BaseCallbackHandler`. It provides the asynchronous counterpart to the synchronous callback handlers.

*   **[base_handlers](base_handlers.md)**: The `AsyncCallbackHandler` extends `BaseCallbackHandler`, providing asynchronous implementations for the callback interface.
*   **[core_messages](core_messages.md)**: The `on_chat_model_start` method specifically handles `BaseMessage` objects from this module.
*   **[core_agents](core_agents.md)**: `on_agent_action` and `on_agent_finish` methods interact with `AgentAction` and `AgentFinish` types, likely defined or used within the `core_agents` module.
*   **[core_retrievers](core_retrievers.md)**: The `on_retriever_end` method uses `Document` objects, which are typically handled by or originate from retriever components.

This comprehensive set of asynchronous callbacks allows developers to build robust and performant applications that require real-time monitoring, logging, or custom processing of events throughout the LangChain execution flow.
