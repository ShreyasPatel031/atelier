# embedded_test_support

## Introduction
The `embedded_test_support` module provides a crucial utility for testing embedded software by orchestrating the compilation and execution of code on various QEMU-simulated embedded platforms. It simplifies the process of setting up target-specific compiler flags and running tests in a controlled virtual environment.

## Purpose and Core Functionality
This module's primary purpose is to facilitate the development and testing of embedded applications by providing a consistent interface for:
*   **Device Configuration:** Supporting different embedded targets like ARM (STM32F1, STM32F4), AVR (ATMega2560), and RISC-V (virt) through QEMU.
*   **Compiler Flag Generation:** Automatically generating correct C, Swift, and Swift-frontend compiler and linker flags for the selected embedded target, including necessary support libraries and linker scripts.
*   **Test Execution:** Running compiled ELF (Executable and Linkable Format) files on the configured QEMU instance, with options for semi-hosting.
*   **Demo Execution:** Providing a quick way to run a built-in demo application for a given device.
*   **Flag Printing:** Allowing developers to inspect the generated C, Swift, or Swift-frontend flags for debugging or integration purposes.

The module encapsulates the complexities of cross-compilation and embedded environment setup, making it easier to integrate embedded testing into CI/CD pipelines or local development workflows.

## Architecture and Component Relationships

The `embedded_test_support` module is centered around its `main` function, which acts as the command-line interface and orchestrator for all its functionalities. It parses arguments, configures the build and run environment based on the selected device, and executes external tools like `clang`, `qemu-system-arm`, `qemu-system-avr`, `qemu-system-riscv32`, and `expect`.

The `main` function dynamically determines the correct compiler targets, QEMU binaries, machine types, and linker configurations based on the `--device` argument. It then constructs appropriate command-line arguments for `clang` to compile support libraries (`support.c`, `libc.c`, `demo.c`) and user-provided ELF files. For execution, it constructs and runs `qemu` commands within an `expect` script to capture output and manage execution flow.

## How the Module Fits into the Overall System
The `embedded_test_support` module is a vital part of the larger [test_generation_and_update](test_generation_and_update.md) system. It provides the execution environment necessary for running tests that are either generated by other tools or verified against expectations.

Specifically, it works in conjunction with:
*   **[generated_test_updater](generated_test_updater.md):** While `generated_test_updater` is responsible for creating or updating test cases, `embedded_test_support` provides the mechanism to compile and run these generated tests on actual or simulated embedded hardware to ensure their correctness.
*   **[verify_test_updater](verify_test_updater.md):** Similarly, for verification tests, `embedded_test_support` offers the runtime environment where the tests can be executed, and their behavior observed, often as part of updating or verifying test expectations handled by the `verify_test_updater` and its sub-modules like [test_expectation_handler](test_expectation_handler.md) and [expectation_updater](expectation_updater.md).

By centralizing the logic for embedded compilation and execution, `embedded_test_support` ensures consistency and reduces boilerplate across various testing and update utilities within the system.
