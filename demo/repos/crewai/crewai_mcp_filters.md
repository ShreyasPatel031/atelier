# `crewai_mcp_filters` Module Documentation

## Introduction

The `crewai_mcp_filters` module is responsible for providing utility functions to create tool filters within the CrewAI Model Context Protocol (MCP) ecosystem. These filters allow developers to define policies for tool usage, specifying which tools are allowed or blocked during agent execution, thereby enhancing security and control over agent capabilities.

## Comprehensive Documentation

### Purpose and Core Functionality

The primary purpose of this module is to offer a straightforward way to construct "static" tool filters. A static tool filter is a function that, when given information about a tool, determines whether that tool should be permitted to execute based on predefined allowlists and blocklists.

The core functionality revolves around the `create_static_tool_filter` function. This function acts as a factory, generating a callable filter that can be integrated into various components of the MCP server. By using this module, developers can easily implement tool access control, ensuring that agents only interact with approved tools.

### Architecture and Component Relationships

#### `create_static_tool_filter`
This is the main public function of the module. It takes lists of `allowed_tool_names` and `blocked_tool_names` and returns a filter function. Internally, it instantiates a `StaticToolFilter` object (whose implementation details are internal to this module but provide the actual filtering logic based on the allow/block lists).

#### `StaticToolFilter` (Internal Representation)
This represents the internal logic that processes the `allowed_tool_names` and `blocked_tool_names` to produce the final boolean decision for a given tool. Blocked tools always take precedence over allowed tools.

### How the Module Fits into the Overall System

The `crewai_mcp_filters` module is a critical policy enforcement layer for the CrewAI system when operating with the Model Context Protocol (MCP). It allows system administrators or developers to define tool usage policies that govern the interactions of agents with external tools. For instance, an MCP server (like `MCPServerStdio` as shown in the example) would consume the filter function generated by this module to restrict the tools available to an agent. This integration ensures a secure and controlled execution environment for AI agents, preventing unauthorized actions and maintaining system integrity.
